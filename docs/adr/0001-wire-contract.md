# ADR 0001 - Wire contract: Typeshare, Schemars, UniFFI

- Status: **proposed** - spike not run, no bindings generated
- Date: 2026-10-19
- Wave: 0 (decision recorded), spike still open
- Related: locked amendments 8, 13

## Context

Three consumers read the same wire types: the Rust daemon (`eris-host`), the web
UI (TypeScript), and the iOS surface (Swift, through UniFFI). Keeping three hand
written copies is how a product ends up with two wire formats and a silent
mismatch.

Locked amendment 8 says JSON Schema is not automatically three languages, and it
requires the spike to prove itself before anything is adopted. Amendment 8 also
names the preference order: Rust wire types with `serde(tag = "type")` as the
source of truth, Typeshare for TypeScript and Swift, Schemars for schema, and
golden fixtures. Typify plus Draft 2020-12 is the fallback only if the spike
proves unions round-trip. No quicktype.

## Decision (proposed, pending the spike)

1. **Source of truth** is a Rust type in `core-domain` with
   `#[serde(tag = "type", rename_all = "snake_case")]` for every union. This is
   already how `EventKind` is written.
2. **TypeScript and Swift** are generated by Typeshare 1.0.5.
3. **JSON Schema** is generated by Schemars 1.2.3 from the same types.
4. **FFI surface**: UniFFI 0.32.2 carries function calls for the Lite core. It
   does not carry the event log wire format, which stays JSON.
5. **Golden fixtures** live in `contract/fixtures/`, one file per type, and a
   round-trip test in each consumer language parses them unedited. Generated
   output goes to `contract/gen/`, which is gitignored.

Generating into `contract/gen/` rather than into the consumers' source trees
keeps one artefact per language that a reviewer can diff, and keeps a failed
generation from leaving a half-updated tree behind.

## Consequences

- The Rust types are load-bearing for two other languages, so a breaking change
  to them is a breaking wire change. That is the intent: one place to change.
- The generated Swift must compile on the build Mac, which is the only machine with
  Xcode. A TS-only pass is not proof.
- If Typeshare cannot express an internally tagged enum faithfully, the fallback
  is Typify plus Draft 2020-12, which changes the pipeline for all three
  languages. That is why the spike runs before any code depends on the pipeline.

## VERIFY (none of these have been run)

- VERIFY: Typeshare 1.0.5 turns `#[serde(tag = "type")]` on `EventKind` into a
  TypeScript discriminated union rather than a single flat interface.
- VERIFY: Typeshare 1.0.5 emits a Swift enum with associated values for the same
  type, and it compiles under the pinned Xcode on the build Mac.
- VERIFY: Schemars 1.2.3 derives from the identical type without needing
  `#[schemars(...)]` attributes that contradict the serde ones, in particular for
  `Option<T>` and for the internally tagged enum.
- VERIFY: the `deny_unknown_fields` policy survives into the generated schema, so
  schema validation and serde agree on an unknown-field rejection.
- VERIFY: snake_case wire names survive Swift `Codable` without hand written
  `CodingKeys`, and TS without a name mapping table.
- VERIFY: one golden fixture per `EventKind` variant parses in Rust, in TS via
  `tsc`, and in Swift via `swiftc`, with no per-language edit.
- VERIFY: a union round-trips under Typify plus Draft 2020-12, before the fallback
  is adopted for real.
- VERIFY: UniFFI 0.32.2 proc-macro surface builds on this host for
  `x86_64-unknown-linux-gnu` and generates Swift bindings on the build Mac.
- VERIFY: `cargo build` cost of the added proc-macro crates is acceptable in CI.

## Not in this ADR

P1 generates nothing. No bindings, no schema files, no `contract/gen/` contents.
The spike runs as its own task, and every VERIFY above must be replaced with a
result before this ADR moves from proposed to accepted.
